# api-hg infrastructure inventory

| # | Component | Where | Used by | Holds |
|---|---|---|---|---|
| 1 | Functions `<env>-hg-<slug>` (13 routes + `migrate`), ARM64 Node 22, in the platform VPC | CDK stacks `<env>-ApiHg<Slug>` | front-self (player), backoffice (operator), the provider (webhook) | nothing persistent |
| 2 | Execution roles `<env>-hg-<slug>-exec` | same stacks | the functions | own log group, read of the three secrets, wallet invoker policy, VPC ENI |
| 3 | Security group `<env>-hg-<slug>-egress` per function + ingress rule on the database SG | same stacks | functions → database | — |
| 4 | Webhook Function URL (auth NONE, HMAC-verified in code) | stack `<env>-ApiHgWebhook`; published at `/<env>/api-hg-lambda/webhook-function-url` | hg.cash callbacks | — |
| 5 | Aurora Serverless v2 Postgres `<env>-hg-postgres`, database `payments`, TLS forced, encrypted, snapshot on removal | CDK stack `<env>-HgDatabase` | the functions only | `payment`, `payment_event`, `webhook_inbox`, `payment_settings`, `schema_migrations` |
| 6 | Secret `<env>/HgDatabase/postgres` (generated by RDS) | same stack | functions (`DB_SECRET_ARN`) | DB credential |
| 7 | Secret `<env>/HgSecrets` | `scripts/bootstrap-ssm.sh` | functions (`HG_SECRET_ARN`) | `PROVIDER_API_TOKEN`, `PROVIDER_WEBHOOK_SECRET`, `WALLET_API_KEY` |
| 8 | Secret `<env>/JWTSecret` (platform-owned) | platform | functions | the token secret |
| 9 | SSM `/<env>/api-hg-lambda/*` | `scripts/bootstrap-ssm.sh` (app values), database stack (`db-*`), webhook stack (`webhook-function-url`), resource-group stack (`*-invoker-policy-arn`) | CDK synth/deploy, caller roles | non-secret URLs, ids, names |
| 10 | Managed policies `<env>-api-hg-player-invoker`, `<env>-api-hg-operator-invoker` | CDK stack `<env>-ApiHgResourceGroup` | front-self / backoffice task roles | — |
| 11 | Resource group `<env>-api-hg-lambda` (tags Application=api-hg-lambda, Environment) | same stack | console / cost | — |
| 12 | Log groups `/aws/lambda/<env>-hg-<slug>`, 14 days, destroyed with the stack (`RETAIN_LOG_GROUPS=true` to keep) | function stacks | CloudWatch | logs |
| 13 | Wallet invoker policy `/<env>/api-wallet-lambda/invoker-policy-arn` (owned by wallet-lambda) | read at deploy | execution roles when `WALLET_MODE=lambda` | — |
| 14 | Local: Postgres container `hg-postgres` on 5433 (`infra/docker-compose.yml`) | developer machine | `npm run server` | local data |

Platform-owned, must exist before deploying: `/<env>/VpcId`,
`/<env>/PrivateSubnet1`, `/<env>/PrivateSubnet2`, optional
`/<env>/ClientSecurityGroupId`, `/<env>/MainOtelEndpoint`, secret
`<env>/JWTSecret`.

External: hg.cash API (`PROVIDER_API_URL`, production `https://hg.cash/api/v1`),
one hg.cash account (`PROVIDER_ACCOUNT_ID`) that collects checkouts and pays
transfers; webhook URL + signing secret are registered in its dashboard.

## Order of deployment

`cdk deploy --all`: resource group → database → webhook → other functions
(they read the webhook URL from SSM) → `migrate` invoked by the npm script.
`deploy:all` in `cdk/package.json` does all of it.

## Not here

No Redis, no SNS, no API Gateway. The provider reaches the webhook through a
Lambda Function URL (or `provider-webhook-url` when an ingress fronts the HTTP
runtime). The wallet database is never touched.
